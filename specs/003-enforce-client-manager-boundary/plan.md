# Implementation Plan: Enforce Client–Manager Layer Boundary

**Branch**: `003-enforce-client-manager-boundary` | **Date**: 2026-04-12 | **Spec**: [spec.md](./spec.md)

## Summary

Add a `validate` operation to `IDeploymentManager` and its implementation in `DeploymentManager` (delegating to `IShippingEngine`), then remove the Engine dependency from `DeployCLI` and re-route all credential-validation calls through the Manager. This eliminates the CLAUDE.md violation where the Client directly called an Engine.

### Step 2 — Implement `validate` in `DeploymentManager`

**File**: `src/managers/DeploymentManager.ts`

Add the `validate` method. `this.shipping` is already in scope:

```typescript
async validate(request: DeploymentRequest): Promise<ValidationResult> {
  return this.shipping.validateCredentials(request);
}
```

Also update the return type import at the top to include `ValidationResult`.

it('returns valid=true when shipping.validateCredentials resolves valid', async () => {
